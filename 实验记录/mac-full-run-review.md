# Mac 全量耗时技术审核

## 现象

- 纽约 2026-11-11 21:15:21 至 2026-11-12 02:34:48，耗时 5 小时 19 分 27 秒；步骤和验收见[步骤](../报告/mac/步骤.json)、[验收](../报告/mac/验收.json)。
- 正式参照 71.5 分钟；Chrome 自己的差 83.4 分钟，其中 GPU 出图 70.4 分钟；实验 1 两遍分别 76.7、84.5 分钟。
- 四轮各覆盖 1,509 动作、8,722 帧，合计 6,036 动作轮次、34,888 帧次；正式轮含既有缓存。来源为正式、GPU、`repeat/first`、`repeat/second` 的参照报告。

## 原因

- 已确认四轮串行执行；重复两遍使用 `cache:false`。全量为单 worker、数值库线程 1、`nice -n 10`。
- 每帧生成活图和冻结图，各截到连续两次 PNG 字节相同；还做冻结值校验、比对、指令、值表和文件写入。Claude 已用独立探针测量，样本数字见[提速方案](full-run-speedup.md)。
- CPU 缓存复核命中 1,509 动作，耗时约 23 秒；两种 Skia 编译均为 `ninja: no work to do.`，固定依赖复用。原始日志在 `out/mac/运行日志.txt`。

## 改法

- 下一次本来就需要全量时，由接手编码代理按[提速方案](full-run-speedup.md)验证复用正式参照、辅助遍只出冻结图、活图页复用，再与当次工具修改合并。
- 先用单素材和快速模式核对冻结 PNG、时间表、指令及指标；更新受影响的工具指纹和实验 5 校准，再做全量。
- 本轮按原流程结束；worker 数量遵守全机计算预算。
