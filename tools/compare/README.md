# 图像对照工具

只用 Node.js 24 与固定 `pngjs@7.0.0`，没有原生扩展、浏览器或在线资源。读写 PNG 不会改动输入图片或旁边的元数据。

## 命令

```sh
npm run compare -- 甲.png 乙.png --线 静止 --报告 out/报告/对照
npm run compare -- out/linux/ref out/mac/ref --线 静止 --报告 out/报告/两平台
npm run check:compare -- --4k --结果=out/报告/对照自测.json
```

对应入口为 `node tools/compare/cli.mjs` 与 `node tools/compare/self-test.mjs`。目录递归按相对路径配对 PNG；任何一侧缺图、两侧类型不同或空目录都是错误。退出码：全部通过 **0**，有指标未通过 **1**，尺寸、配对、PNG、元数据等错误 **2**。每对图出错会继续比剩余图并写入报告，不把错误算作跳过或通过。

可选参数：

- `--线 静止|运动|GPU`，默认静止。文字区域自动改用文字线。
- `--报告 目录`，默认 `out/报告/对照`。
- `--倍率 数字`，覆盖图片元数据及文件名中的倍率。必须大于 0。
- `--阈值 文件.json`，默认读取工作目录的 `阈值.json`，不存在时用需求规定的起步值。
- `--GPU基准 文件.json`，GPU 线必需；缺某帧会明确报错，不能拿别的图替代。

`index.html` 完全独立，所有图片以 data URL 内嵌，可直接双击或转交。`结果.json` 含相同信息，包括图片、各区域指标、实际阈值、失败原因、汇总和耗时。网页的甲图可点击来回切换甲乙。差异放大 8 倍，绿色突出不算作边的大差像素。图片按 SSIM 从低到高排列；汇总统计实际参与判定的区域，文字与非文字单独计入。超过一个区域时，全图指标仅供参考。

## 图片元数据

参照图 `0@2x.png` 旁边放 `0@2x.json`：

```json
{
  "倍率": 2,
  "文字区域": [{"x": 120.5, "y": 80, "width": 240, "height": 48}]
}
```

包围盒是**最终 PNG 像素坐标**，不能再次乘倍率。矩形向外扩 2 像素，与像素格相交即纳入，重叠矩形取并集。文字与非文字都只在内容区域内计数。只读取甲的元数据，甲应是参照图。也兼容 `scale`、`textBoxes`、`textRegions` 和每项的 `bbox` 对象。无元数据时从文件名 `@2x.png` 推断倍率，再没有则用 1。元数据损坏不是“无文字”，会报错。

## 阈值文件格式

所有比例是 0 到 1 的比值，例如 0.001 就是 0.1%，不写百分号。默认值：

```json
{
  "静止": {"ssim": 0.995, "大差比例_不算边": 0.001, "最大差异块": 16, "平均偏色": 1},
  "文字": {"ssim": 0.98, "大差比例_不算边": 0.005, "最大差异块": 16, "平均偏色": 1},
  "运动": {"ssim": 0.975, "ssim_2倍": 0.985, "大差比例_不算边": 0.01, "最大差异块": 32, "平均偏色": 1.5},
  "GPU": {"ssim": 0.995, "大差比例_不算边": 0.002, "最大差异块": 16, "平均偏色": 1.5}
}
```

可以只覆盖某条线，但一旦覆盖这条线，必须提供完整的四项指标。最大差异块阈值在判定时乘**倍率平方**；运动在倍率不小于 2 时采用 `ssim_2倍`。

GPU 基准按相对 PNG 路径组织；单文件比较用甲文件名。示例：

```json
{
  "帧": {
    "某素材/待机/0@1x.png": {
      "ssim": 0.999,
      "大差比例_不算边": 0.0001,
      "最大差异块": 4,
      "平均偏色": 0.1
    }
  }
}
```

有文字时可以把每帧改成 `{"全图":{...},"非文字":{...}}`，文字始终按文字线。GPU 的“不能比它差两成”按**误差增加不超过20%**实现：SSIM 的误差是 `1−SSIM`，其余三项本身就是误差。再与保底线取较严格者。基准最大块已经是该帧倍率下的实测像素数，不再乘倍率。这样零误差基准会要求零误差，报告会列明实际阈值；需由 Fable 确认最终阈值。

## 算法与精度

- 两张图均按原始 RGBA 读入，alpha>0 的并集做 5 像素方形外扩。
- 深底 32、浅底 224 均按浮点 alpha 合成。两种底分别完整计算，再按原始双精度 SSIM 选择更差的结果。相等时取深底，不在比较前舍入。
- SSIM 用亮度、11×11 高斯窗、σ=1.5、镜像补边（边缘像素不重复，等价于 NumPy reflect），C1=6.5025、C2=58.5225。尺寸为 1 的轴重复唯一像素。
- 大差阈值严格 `>16`；三个通道均须满足双向 3×3 邻域范围 ±16 才能算作边。邻域在整张图上读取，不裁在文字边界上。
- 最大块先保留属于完整 2×2 小方块的像素，再按八邻域求连通分量。文字与非文字的连通块分别处理，不跨区域。
- 平均偏色是带符号 RGB 通道平均差绝对值的最大值。`平均绝对差` 是区域内三通道绝对差的平均；旧 Python 的 `平均差` 是每点**最大通道差**的平均，二者不是一个指标。
- 逐项输出未舍入的数值，HTML仅格式化显示；阈值判定使用原始数字。空内容或空区域的 SSIM=1，其余指标=0。

`metrics.mjs` 导出 `compareImages(a,b,options)`。图片对象为 `{width,height,data}`，data 为 RGBA 字节。返回 `分组`、`通过`、`差异图` 等。`cli.mjs` 导出 `compareFiles(a,b,options)`，同时负责读取 PNG 和元数据。

## 自测与验收边界

自测生成需求中的八类图，另测小尺寸镜像、透明图、内容外扩、八邻域、倍率、GPU缺基准、CLI退出码、目录配对和离线报告。用五个仓库真实 PNG 分别施加确定的颜色差、透明度差和平移，与 `docs/试验/比较.py` 对数。原试验版没有平均偏色，因此只读导入其函数，在测试进程里用 NumPy 独立补算，不修改文档或素材，也禁止生成 Python 字节码缓存。SSIM、平均偏色、连边大差比例误差要求 ≤0.001。它的最大块没有去细线，不能拿来检查新版最大块。

Python对数依赖 `python3`、NumPy 和 Pillow；缺少会使检查失败，而非跳过。安装命令：`python3 -m pip install numpy Pillow`（环境限制时用虚拟环境）。工具本体不依赖 Python。

`--4k` 使用全图有内容且非相同的3840×2160图，端到端计时包含新 Node 进程启动、PNG读取、两底计算、差异PNG编码、HTML及JSON落盘，要求低于5000毫秒。2026-11-11 Linux x86_64、Node v24.22.1，优化后冷进程实测：

| 场景 | 端到端耗时 | 峰值常驻内存 |
|---|---:|---:|
| 不透明、全内容、非相同 | 2921.5 毫秒 | 357.6 MiB |
| 半透明、全内容、非相同、实际计算两底 | 4094.7 毫秒 | 371.9 MiB |

内存按子进程 `process.resourceUsage().maxRSS` 记录。工具只缓存两张亮度图，RGB合成和差异在线计算；五项高斯矩只缓存11行。全不透明时两底数学等价，复用结果；半透明不会走这个优化。

早期全图RGB双精度中间数组版本，在并行构建时曾实测5282毫秒、5189毫秒而失败。已改为在线合成以降低内存和耗时，不删除或掩盖这些已知历史失败。最新两类均过；完整机器实况以每次 `--结果` 输出为准，失败同样写结果。

只在 Linux 测过，不代表 Mac 已验收。性能会受同机并行任务负载影响，不可省略失败。
