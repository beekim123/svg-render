缓存／覆盖隔离单元测试全部通过：

- 参照身份和缓存键必须记录实际策略；缺策略不能补默认。

此前100个UI帧及52个char_golem帧是当时总启用保层候选的历史实测；原记录保留。本轮没有重跑152帧，也不能把旧记录当作新默认策略的验收证据。

## API与隔离规则

`installTimeline({freezePolicy})`显式接收策略。`createReferenceSession()`读取参照版本.json，缺策略配置时仍默认value-only；未知值先拒绝再开Chrome。session.freezePolicy、帧metadata.冻结策略、批报告及动作摘要均记录实际策略。

候选仅可显式调用：

```js
const session = await createReferenceSession({freezePolicy: 'preserve-layers'});
await runBatch({manifest, out, concurrency: 1,
  sessionOptions: {freezePolicy: 'preserve-layers'}});
await checkCoverage({manifest, out,
  expectedFreezePolicy: 'preserve-layers'});
```

默认调用不带候选参数。check-composite现明确使用候选sessionOptions；默认／候选的两帧对照由check-freeze-policy提供。两策略不得共用缓存身份；旧无策略记录不能被重新贴标签通过。

生产文件已冻结，SHA256见“生产与测试SHA256.txt”。本轮仅增加audit.checkCoverage的expectedFreezePolicy入参及refresh透传，未更改重复性或噪声合格聚合口径。
