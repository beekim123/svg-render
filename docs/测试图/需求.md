# 复杂 SVG 测试图

## 1 这批图拿来干什么

我们在做一套 SVG 渲染工具：游戏直接用 SVG，不再先转成一帧一帧的 PNG。要求是画得和 Chrome 一样，一屏有很多 SVG 也流畅。

这批图是**测试用的**，不进游戏。它用来测两件事：画得像不像，跑不跑得动。所以要尽量丰富、尽量难。

**和以前的美术包正好相反：这次不限"简单形状"，越丰富越好。** 但要像真的游戏画面，不要堆随机图形。题材是哥特古堡里的卡牌游戏：怪物、古堡场景、宝石、魔法特效、卡牌。全部原创，不要照着现有的游戏画。

### 2.1 故意要放进去的难点

渲染工具最容易在下面这几种情况画错，所以每种至少要出现一次：

- **混合模式叠在会动的东西上**：比如 `scene_hall` 里用 screen 的光柱，下面压着正在飘的雾。
- **半透明的组里，子元素各自在动、又互相重叠**：`char_swarm`。
- **滤镜加在一个整组上，组里还有东西在动**：比如 `char_lich` 整体外发光，同时披风在飘。
- **遮罩在动，被遮住的内容也在动**：`fx_circle`。
- **同一个渐变或 pattern 被很多元素引用**：`scene_vault`。
- **滤镜参数本身在动**：模糊半径、噪声频率、置换强度。
- **路径形变**：前后两个路径的点数和命令要一致，不然 Chrome 不会平滑过渡。

## 3 规矩

1. **以 Chrome 为准**。每个图在最新的稳定版 Chrome 里打开都要画对，动画要流畅；用的 Chrome 版本写进 `notes.md`。Firefox 和 Safari 不用管。
2. **每个文件自己就是完整的**：
   - 不外链任何东西（图片、字体、CSS 文件）；
   - 不用 `<script>`；
   - 不用 `<foreignObject>`；
   - 不嵌位图（`<image>` 里放 PNG 或 JPG 都不行）。
3. **文字**一律用 `Noto Sans CJK SC`。包里的 `字体/` 文件夹有这个字体，先装到系统里再用 Chrome 看。只有 `card_foil`、`fx_circle`、`ui_hud` 三个需要文字。
4. **动画**：
   - CSS `@keyframes` 和 SMIL（`<animate>` `<animateTransform>` `<animateMotion>` `<set>`）**两种都要用到**。每个文件用了哪种，在 `notes.md` 里写清楚。
   - 循环的动画首尾要接得上。
   - 一次性的动作（施法、受击、爆炸、闪电）：用 CSS 写的，给根元素加一个 class 来触发（比如 `class="act-cast"`）；用 SMIL 写的，`begin="indefinite"`，我们这边用脚本触发。在 `notes.md` 写清楚怎么触发。
5. 每个文件的根元素上写 `viewBox`，并写上相同的 `width` 和 `height`。文件名就是 id。
6. 第 2 节"要用到的东西"那一列尽量都用上。用不上的，在 `notes.md` 里说明原因。
7. **不用担心性能，越难越好**。但要好看，像真的游戏画面。

## 4 交付

放进 `交回/out/`：

- 10 个 `<id>.svg`，加上 `icons/` 文件夹里的 30 个 `icon_<名字>.svg`；
- 每个图一张 PNG 预览：在 Chrome 里截的静止画面，1 倍大小，文件名和 SVG 一样；
- `notes.md`，每个文件写一节：
  - 用到了哪些特性：元素、滤镜、混合模式、mask 和 clip、pattern、文字；
  - 动画清单：哪个元素、动的是什么属性、用 CSS 还是 SMIL、时长、循不循环、怎么触发；
  - 元素个数、文件大小；
  - 你觉得最难画对的地方；
  - 用的 Chrome 版本。
