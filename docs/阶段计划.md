## 阶段 1：编译器、素材文件、用 CPU 把静态图画对

**开始前要过的实验**：实验 1、2、4（mac 部分）、5 都及格。实验 6 有结论（及格或者已经换方案）。

**做什么**：

- 编译器前半：从 Chrome 导出"场景文件"（节点、样式、几何、资源、文字的字形位置；use 展开；currentColor 探测）。
- 编译器后半：节点树、资源表、合并相同子树、量化、读写 `.svgbin`。
- 内核的静态绘制：照 Blink 的方式给 Skia 发指令，覆盖 `设计.md` 1.2 节"支持"栏里所有静态特性。
- 命令行出图：给素材、时刻、倍率，画成 PNG。
- 静止帧自检，接进编译流程。
- 素材检查工具（在阶段 0 的特性清单上加规则）。

**这个阶段不做动画求值**。某一时刻的画面，各个动画值由 Chrome 给（前半按参照时刻各导一份），内核只管画。这样"画得对不对"和"值算得对不对"分开验。

**里程碑**（按特性一类一类过线）：

| | 特性 | 过线的素材 |
|---|---|---|
| 1a | 形状、描边、纯色、渐变、变换、透明度、use | 现有游戏 117 个全部过 |
| 1b | 裁剪、遮罩、pattern、marker、混合模式、组透明度 | 测试图里不带滤镜和文字的部分 |
| 1c | 滤镜：先模糊、投影、合并、颜色矩阵、填色、合成、混合；再噪声、置换、形态学；最后光照、卷积、平铺、分量变换 | 测试图 |
| 1d | 文字 | card_foil、fx_circle、ui_hud |

**交什么**：

- 代码：编译器、内核、命令行工具。
- 《素材文件格式说明》：精确到每个段、每个字段的字节。
- 《Blink 对照表》：每个 SVG 特性对应 Skia 的哪些调用、标志位，出自 Blink 的哪个文件，Chrome 指令记录里的样子。
- 编译报告、对照报告、速度基准表、《未达标清单》。

**怎么验收**（自动）：

| # | 检查 | 及格线 |
|---|---|---|
| 1 | 现有游戏 117 个 SVG，所有动作的所有参照时刻，1 倍和 2 倍 | 100% 过静止帧的线 |
| 2 | 测试图 10 张加 30 个图标，所有参照时刻，1 倍和 2 倍 | ≥ 95% 的帧过线（文字区域按文字的线）；没过的每一帧都在《未达标清单》里有原因 |
| 3 | 公开测试集里属于支持范围的（resvg 测试集为主），参照用我们自己的 Chrome 重出 | ≥ 90% 过线；按特性分别给通过率 |
| 4 | 读写往返：编译 → 读回 → 再画 | 和直接画逐字节相同 |
| 5 | 量化：默认步长下，放大 4 倍的帧 | 过静止帧的线 |
| 6 | **实验 11 包体** | 现有 117 个合计 ≤ 300 KB；每个文件 ≤ 对应 SVG 文本的 35% |
| 7 | **实验 12 光栅速度基准** | 交一张表：填充、渐变、每种滤镜的每核每秒像素数；每张测试图首次全画的毫秒数。参考线：scene_hall 1 倍单线程 ≤ 1.5 秒（Chrome 自己连解析约 0.8 秒），char_lich ≤ 150 毫秒。没到参考线不挡验收，但要给解释，我据此改 `设计.md` 第 3 节和后面的预算 |
| 8 | 二进制 | mac 两种架构，内核加 Skia 的动态库各 ≤ 8 MB |
| 9 | 素材检查 | 对全部素材跑通，报告和特性清单一致 |

## 阶段 2：动画、分层缓存、调度、接入 Godot（mac）

**开始前要过的实验**（用阶段 1 的命令行工具就能做，不用等接入）：

| 实验 | 做法 | 及格线 | 不及格怎么办 |
|---|---|---|---|
| **8 动画取值** | 先把时间线求值器做出来（这是本阶段第一个里程碑）。全部素材、全部动作，每 20 毫秒算一次，和阶段 0 的动画值表比 | 现有游戏：100% 的轨由运行时算就过线。测试图：≥ 90% 的轨由运行时算过线，其余自动改成采样轨后 100% 过线。采样轨让文件增大不超过 30% | 哪类轨大面积对不上，就补那一类的求值；文件增大超了，我看是哪种动画，决定是补求值还是放宽 |
| **9 缓存的代价** | 用命令行工具模拟：把层按倍率档画成缓存，再按动画里的变换用双线性取样合成，和冻结图比。档距试 √2 和 1.26，缓存倍率系数试 1.0、1.25、1.5。另量一组：实例静止在 0.55、0.8、1.3 倍时，用按档的缓存缩着画，对同倍率的冻结图差多少（只交数字，用来确认"停稳后按实际倍率重画"这条规则有没有必要、上限 4 张够不够） | 档距 √2、系数 1.0 时，≥ 90% 的运动帧过运动中的线 | 系数升到 1.25，我重算显存预算。如果要到 1.5 才行，回来找你商量，因为显存会翻一倍多 |
| **10 Godot 上传和合成开销** | 一个最小的 GDExtension，只测三件事，Compatibility 和 Mobile 各测一遍 | ① 整张上传一张 4 MB 的纹理，主线程耗时 ≤ 2 毫秒；② 3000 个每帧都在动的贴图四边形（比较"每层一个画布项"和"MultiMesh"两种做法），主线程提交 ≤ 1.5 毫秒，2560×1440 下 GPU 帧时间 ≤ 4 毫秒；③ 用 DrawableTexture 往图集页的某一块里画，连续跑 1 小时不崩、显存不涨 | ①不及格：重画层改走 DrawableTexture 局部更新；还不行，评估换 Mobile 渲染器。②选及格的那种做法；都不及格，回来找我。③不及格：阶段 4 的离屏通道改用 SubViewport |

**做什么**：

- 时间线求值器；编译器的时间线自检和采样兜底。
- 动作的语义（切换时哪些动画接着走、哪些重来）。
- 编译器里的分层；层的包围盒、降分辨率判断。
- 缓存：图集、倍率档、瓦片、淘汰；整圈缓存；实例分组共用。
- 调度：线程池、每帧预算、提前一帧画、预热。
- 染色的三条路（单色、双图、按颜色重画）和自动判断。
- 离屏组的 CPU 版。
- 降级控制，级别 0–5。
- Godot 接入：`SvgAsset`、`SvgSprite2D`、`SvgServer`；六种着色器；槽；跨素材的四种混合。
- 压测场景；引擎内截图对照。

**交什么**：代码；GDExtension（mac 通用二进制）；一个演示工程；压测工程和三组结果；对照报告；《接入说明》。

**怎么验收**（自动）：

| # | 检查 | 及格线 |
|---|---|---|
| 1 | 时间：全部素材、全部动作、每 20 毫秒的动画值；另加 3 组"动作切换时间表" | 100% 过 `设计.md` 2.3 节的时间线 |
| 2 | 引擎内静止帧：Godot 里把实例画到离屏再存图，对冻结图。Compatibility 和 Mobile 各跑一遍 | 停稳 0.2 秒后，过静止帧的线。范围：现有游戏全部；测试图里不需要 GPU 滤镜也能跑的部分 |
| 3 | 引擎内运动帧 | 过运动中的线 |
| 3b | **停在两档之间的静止实例**：实例以 0.55、0.8、1.3 倍，以及 0.8 倍加转 10 度，位置在整像素上，停 0.2 秒后截图。参照是 Chrome 以同样倍率、同样转角画的冻结图 | 过**静止帧**的线（不是运动中的线）。另测：同一素材 6 种不同的静止倍率同屏时，4 个过静止帧的线，另 2 个过运动中的线，统计里"没定稿的静止实例"= 2；实例一动再停回原倍率，不重新栅格化 |
| 4 | 压测甲：同一个图标 300 个实例，位置、缩放、旋转都在变，三分之一带动画 | 60 帧（99% 的帧 ≤ 16.7 毫秒）；主线程里内核的耗时 ≤ 2 毫秒；绘制调用 ≤ 30 |
| 5 | 压测乙：40 种素材 150 个实例，加 2 张场景当背景（只开缓存加合成撑得住的动画） | 60 帧；显存 ≤ 384 MB；冷启动预热 ≤ 3 秒 |
| 6 | 压测丙：会变形的素材比例取 0、10%、20%、30%、50% | 10% 时 60 帧；30% 时 ≥ 30 帧。记下每一档先到顶的是谁（CPU 栅格化、上传、GPU 填充、显存） |
| 7 | 降级 | 跑检查 1–3 时降级次数 = 0 |
| 8 | 浸泡 | 压测乙连续跑 1 小时：显存不涨，不崩 |
| 9 | 二进制 | GDExtension 的动态库每架构 ≤ 10 MB |

压测条件：你这台 M3，窗口 2560×1440，Compatibility 渲染器；另跑一遍 3840×2160 和 Mobile 渲染器，只记数不设线。

## 阶段 4：丰富画面

**开始前要过的实验**：

| 实验 | 做法 | 及格线 | 不及格怎么办 |
|---|---|---|---|
| **13 GPU 滤镜的一致性和稳定性** | 模糊、投影、颜色矩阵、合成、混合、置换、噪声、光照，每种写一个 GPU 版，对同一输入的 CPU 版结果。Compatibility 和 Mobile 都测 | 每种都过 `设计.md` 2.3 节 GPU 那一行的线；离屏通道连续跑 1 小时不崩、不漏、不闪 | 过不了线的那种滤镜留在 CPU 上，只把过了的放到 GPU |
| **14 动态层要不要上 GPU**（有条件才做） | **触发条件**：阶段 2 压测丙在 10% 时到不了 60 帧，或者测试图里有素材长期停在降级 3 级以上。三条路各做一个最小原型：① 条带（CPU 算边缘的覆盖率，GPU 填内部）；② 让 Skia 的 GPU 部分和 Godot 共用设备（只在 Mobile / Forward+）；③ 计算着色器。顺带试 `设计.md` 第 12 节说的"大面积平涂层不存贴图" | 对 CPU 版的相似度 ≥ 0.99；同一场景比 CPU 路线快 3 倍以上；①要在两种渲染器上都能跑，②③要连续跑 1 小时稳定 | 三条路都不及格：保持 CPU 路线，靠降级和整圈缓存；素材检查工具给超预算的素材点名 |

我的倾向是①：它两种渲染器和 H5 都能用，边缘的算法和 Skia 的 CPU 光栅是一类，容易对上。②的风险在同步，而且 H5 用不了。

**做什么**：

- 离屏通道的接口和 Godot 的实现（DrawableTexture）。
- GPU 滤镜的着色器；离屏组的 GPU 版。
- 不变的滤镜也用 GPU 烤，缩短首次显示。
- 磁盘缓存（画好的缓存存到用户目录，下次启动直接读；有上限，默认 256 MB）。
- 降级补全：超预算的素材由检查工具点名。
- 实验 14 被触发并且有及格的路：动态层的 GPU 光栅。

**怎么验收**（自动）：

| # | 检查 | 及格线 |
|---|---|---|

## 评估：把阶段 2 拆成"2 甲"和"2 乙"

**决定（用户，2026-11-11）：不拆。阶段 2、3 按上面的正文执行。** 下面的评估留作记录：我当时的建议是拆，卡牌游戏能提前大约 1–1.5 个月换上，代价是总工作量多 2–3 周，以及下面第 2、3 条风险。

**2 甲要包含什么**（按卡牌游戏实际用到的定。我扫了两份清单里的 117 个素材）：

| 卡牌游戏用到的 | 2 甲里要有 |
|---|---|
| 动画只动变换、透明度，另有 1 个素材（fx_rainbow）动矩形裁剪 | 时间线求值器只做这三种属性；"矩形裁剪"着色器 |
| 7 个染色素材，都是 currentColor 的纯色，没有一个带滤镜，也没有用在渐变里 | 只做单色染色。双图染色、按颜色重画留给 2 乙 |
| 7 个素材带做旧颗粒滤镜，都是静态的 | 不用额外做：阶段 1 已经能把它烤进不变层 |
| 动作：播一次、播完停住、进场后循环 | 动作语义完整做 |
| 槽、锚点、打击点 | 做 |
| 没有路径形变、没有会动的滤镜、遮罩、混合 | 重画层、离屏组、整圈缓存、分组共用、降级控制都不做 |
| — | 分层只分不变层、移动层、单色染色层；图集、倍率档、定稿缓存、预热、淘汰；Godot 接入的三个类和三种着色器（普通、单色染色、矩形裁剪） |

2 甲开始前仍要过实验 8（只对这三种属性）、实验 9、实验 10 的第②项。

**2 乙是剩下的**：其余属性的求值和采样兜底、重画层和它的调度（工作线程每帧出图、提前一帧画、上传预算）、整圈缓存和分组、双图染色和按颜色重画、离屏组的 CPU 版、遮罩相乘和颜色矩阵着色器、跨素材混合、降级控制、压测丙。

**时间**：

| | 不拆 | 拆 |
|---|---|---|
| 阶段 2 | 2–3 个月 | 2 甲 1–1.5 个月 + 2 乙 1.5–2 个月 = 2.5–3.5 个月 |
| 卡牌游戏开始接入 | 阶段 2 全部验收后 | 2 甲验收后，**早 1–1.5 个月** |
| 卡牌游戏接入本身 | 2–4 周 | 2–4 周，可以和 2 乙同时进行（前提是有两个人手，或者 dot 开两条线） |
| 0–4 合计 | 约 7–10 个月 | 约 7.5–10.5 个月 |

**代价和风险**：

1. **总量多 2–3 周。** 多出来的是：验收跑两轮；压测甲、乙在 2 乙做完后要重跑一遍，确认加了重画层的调度没有拖慢只用移动层的场景。
2. **内核接口可能返工一次。** 重画层要每帧换纹理、要上传预算、要工作线程和主线程之间的结果队列；2 甲里这些都用不到，容易写成"缓存画一次就不变"的样子，到 2 乙再改。减轻的办法：2 甲就把 `设计.md` 5.3 节的完整接口定死（`take_uploads` 带预算、合成指令里的纹理号每帧可变、栅格化一律走工作线程），只是重画层那条路没有调用者。这要写进 2 甲的需求，并在验收时用一个假的"每帧换图"的层走一遍接口。
3. **卡牌游戏会跑在一个只验过一半路径的内核上。** 2 乙合进来时，卡牌游戏的整套检查（4866 项和截图对照）要再跑一遍，当作 2 乙的验收项之一。切回精灵图的开关要留到 2 乙验收之后，而不是 2 甲之后。
4. **压测丙（变形比例）推迟到 2 乙。** "动态层要不要上 GPU"（实验 14）的触发条件要等它，所以阶段 4 的范围会晚 1–1.5 个月才能定。阶段 4 排在 2 乙后面，不受实际影响。
5. **卡牌游戏以后加的素材受 2 甲的范围限制**，直到 2 乙完成：不能有路径形变、会动的滤镜或遮罩、非纯色的染色。素材检查工具在 2 甲期间按这个更窄的范围报错。待接入的 35 个素材我扫过，都在范围内。

**不建议再拆得更细**（比如先不做染色）：7 个染色素材现在各烤了 9 种颜色，是纹理里很大的一块，不做染色，换上去的收益就少了一截。
